# horae focus (或 horae do) 任务推荐算法

`horae focus` 是为了终结选择困难症而设计的命令。当你不知道接下来该做什么时，该命令会通过一个**积分加权系统**实时拉取全量活跃任务，对其进行过滤和打分，最终计算并输出**目前最应该做的一件事**。

如果得分相同，系统会优先选择创建时间更早的任务。

## 1. 过滤掉无需立即关注的任务 (Filter)

在进入打分环节之前，系统会先剔除以下不属于当前行动流、或尚未准备好的任务：

* 状态为 `Someday` (将来/也许)、`Reference` (参考资料) 或 `Done` (已完成) 的任务。
* 包含了 `@quote` (金句) 标签的系统任务（它们通常属于参考资料库，不需要被作为待办事项执行）。
* 状态为 `Waiting` (等待中) 的任务：**除非该任务已经逾期**（意味着你需要立即去催促或跟进），否则会被跳过。
* 状态为 `Scheduled` (已排程) 的任务：**除非它已经到达了计划的开始时间 (`scheduled_start_at`)，或者已经逾期**，否则会被跳过。还没到时间的排程任务不会提前出来干扰你。

## 2. 积分加权规则 (Scoring)

针对筛选出来的核心待办事项（主要是 `Inbox`、`Next` 以及当前活跃的 `Scheduled` 和 `Waiting`），系统会从基础 0 分开始进行多个维度的积分叠加：

### 优先级加分 (Priority)
系统最看重你主动标记的优先级（独立 `priority` 字段，由 `!high`/`!medium`/`!low` 或 `--high`/`--medium`/`--low` 设置）。高优任务具有压倒性的分数优势：
* 优先级为 `high`：**+10000 分**（具有绝对的统治力，只要有 high，几乎必定首推）。
* 优先级为 `medium`：**+5000 分**。
* 优先级为 `low`：**+1000 分**。
* 无优先级：不加分。

### 有效截止期加分 (Effective Due)
系统会考察任务的有效截止时间（对于循环任务，则考察它的下一次发生时间），越紧急的分数越高：
* **已逾期**：**+2000 分**。
  * **逾期天数递增惩罚**：在此基础上，每逾期 1 天额外 **+10 分**（最多累计 50 天，即封顶 +500 分）。这意味着当面临两个同样优先级的逾期任务时，逾期更久的那个会被系统判定为更需优先解决。
* **今天截止**：如果距离截止时间不足 1 天（即今天内到期），**+1000 分**。

### 行动状态加分 (Status)
* 状态为 `Next` (下一步行动)：**+500 分**。相较于还未经大脑梳理、停留在 `Inbox` 里的原始任务，系统会利用加分来鼓励你优先执行已经思考清晰并转化为实际行动的 `Next` 任务。

## 3. 决胜条件 (Tie-breaker)

如果经过上述所有维度计算后，有多个任务取得了**完全一样**的分数（例如两个都是 medium，且都没有截止日期），算法会回退到最后一道防线比较它们的 **创建时间 (`created_at`)**：

* **创建越早的任务越优先**（First-In, First-Out）。这也是为了防止堆积在收件箱底部的老旧任务被永远忽视。

---

## 算法实例说明

* 一个停留在 `Inbox` 中、没有设定时间和优先级的普通任务，得分是 **0 分**。
* 一个被整理为 `Next` 的日常任务，得分是 **500 分**。
* 一个带有 `medium` 且今天截止的 `Next` 任务，得分是 `5000 (medium) + 1000 (今天截止) + 500 (Next)` = **6500 分**。
* 而即使是高达 6500 分的紧迫任务，也会被任何一个打上了 `high`（起步 10000 分）的任务无情秒杀。

这个算法的设计初衷就是贯彻 GTD (Getting Things Done) 理念：**永远优先处理你心中定义的最高优先级，其次是消灭即将逾期或已逾期的死线，同时鼓励执行已经梳理好的下一步行动。**
